# 会计对账使用指南

## 典型场景

两份**同结构**明细表逐行比对：

- 应收明细账 ↔ 客户对账单
- 应付明细 ↔ 供应商对账单
- 上期科目余额 ↔ 本期科目余额
- 两套系统（金蝶/用友/Excel）导出的同一张表

示例数据在 `examples/accounting/`，可以直接跑：

```bash
python scripts/reconcile.py run examples/accounting/应收明细账.xlsx \
    examples/accounting/客户对账单.xlsx --key 客户名称 -o accounting-out
```

## 责任边界

只做逐行核对和差异定位，**不判断哪边对**。

对账结果不能直接作为审计证据或税务申报依据，需经注册会计师、税务师复核。
会计责任由单位负责人承担（《会计法》第四条）。

## 三条硬规则

这套工具对会计场景专门做了三件事，和通用数字比较不同：

| 规则 | 为什么 | 实现 |
|---|---|---|
| **金额精确到分** | 0.50 元在 8600 里只占 0.006%，用 1% 相对容差会被当成四舍五入吞掉 | 金额字段用绝对容差 0.005 元 |
| **日期精确到天** | 差一天可能跨期，不能当"写法不同" | 先解析成（年,月,日）再比，不同就报 |
| **按影响金额排序** | 40 条差异里，先看哪条值钱 | 差值 × 数量，降序排 |

> 这两条是实际踩坑后加的：第一次跑会计演示时，8600.50 vs 8600.00 和日期差一天都被判成「一致」。

## 能做什么

| 需求 | 支持 | 说明 |
|---|---|---|
| 金额差异（含小数） | ✅ | 精确到分 |
| 日期差异 | ✅ | 精确到天 |
| 客户/供应商只在一边 | ✅ | 报「仅左/仅右」，并列出该行全部字段 |
| 客户名全称 vs 简称 | ⚠️ | 模糊匹配会给相似度，**建议人工确认** |
| 按金额影响排序 | ✅ | 「优先看这些」段落 |
| 导出 Excel 差异清单 | ✅ | `reconcile-diff.xlsx`，可筛选 |
| 生成修复补丁 | ✅ | `patch` 子命令，生成副本不覆盖原表 |

## 不能做什么

| 需求 | 原因 |
|---|---|
| **一对多匹配**（一笔应收对多笔回款） | 只做一对一按键对齐 |
| 银行流水自动勾对 | 上一条的延伸，需要金额组合搜索，本工具不做 |
| 跨表关联（凭证 → 明细账 → 总账） | 只能两两比，链式勾稽要分步 |
| 按科目树汇总后比 | 需要先在 Excel 里汇总 |
| 判断哪边对 | 只报差异，不判对错 |

## 实操建议

1. **先统一主键**：两张表的客户名/科目编码格式要一致。全称和简称混用会让对齐失败。
2. **加数量列**：有数量时，影响金额 = 单价差 × 数量，排序更准。
3. **看「优先看这些」**：报告最上面按金额影响排序，先处理前 5 条。
4. **红字用负数**：冲销、退款写成负数，工具会计入合计。
5. **改完再跑一次**：用 `patch` + `apply` 生成的副本，再对照一遍，差异应该归零。

## 和进项税勾稽的分工

| 场景 | 用哪个 |
|---|---|
| 两张同结构明细表逐行比 | `reconcile` |
| 凭证进项税额 ↔ 发票税额，按税率分组 | `ledger-match` 的 `vat` 三件套 |

进项税那个是按**税率分组汇总**后比对，不是逐行对，两者互补。
